How the files of a replica of a master (see Make replicas of masters) get from one ESXi host to another.
  • Through the controller (the default): each host sends to Jenkins, which passes it on. It needs nothing of the hosts but the SSH session that each has already, and nothing is unencrypted. It is the slowest, as the bytes make two trips.
  • Directly over SSH: the source host sends to the target. For each copy the source makes a key of its own, and the target accepts it for one command only, unpacking the files in the folder they are going to; both are removed after. The firewall of the source (the sshClient ruleset) is opened for as long as copies need it, if it is not already. The source reaches the target at the address that is configured here. Encrypted, and faster.
  • Directly by netcat: the target listens on a port that is picked at random, and the source connects to it. The firewall of both hosts is opened for that port (a ruleset named jenkinsXfer), and for the address of the source if that is an IPv4 address, and only while the copy goes on. The fastest, but nothing is encrypted: use it only in a network that you trust, as whoever can reach the port while it is open can send files to the folder that the copy is waiting for.
Copies made by Jenkins that do not use this are done as before.
