(Optional, a whole number) What to do when automatic host selection finds no host that the VM can be created on at the moment: how many seconds to wait for one before giving up. This covers every such situation, which the build log names when it happens:
  • the free resource limits rule out every host (busy hosts: expected to pass);
  • no host has the VM's memory size free right now, if Require enough free RAM is on (busy hosts);
  • all hosts are disconnected, in maintenance mode or not among the candidate hosts;
  • no host has enough cores or RAM for the VM, if those requirements are on;
  • no candidate host reports CPU/memory usage statistics.
The value means:
  • 0 (the default): do not wait; give up at once.
  • a positive number: look at the hosts again every 15 seconds for up to that long.
  • -1: wait for as long as it takes (the build can still be aborted).

Giving up means: failing the clone/deploy if it was the free resource limits that ruled out every host (vCenter must not place the VM regardless of them); in all other situations, leaving the placement to vCenter, as was always done. The build log says which of these applies, and whether it will wait, right when the situation is found. A clone or deploy step, or a template, can set its own wait time. A waiting build holds its place in the queue and its connection to vCenter, so a limited wait is advisable on busy farms.
